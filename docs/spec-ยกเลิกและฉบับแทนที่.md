# Spec — ยกเลิก และฉบับแทนที่

อ้างอิง: `docs/00` ข้อปรับเชิงธุรกิจที่ 1, `AGENTS.md`, `docs/01`, `docs/10`  
งาน: DCS-P0-001 | วันที่: 2569-07-16

## เป้าหมาย

รองรับการจัดการเอกสารที่**ออกเลขแล้ว**โดยห้ามแก้ทับเนื้อหา — ใช้การ**ยกเลิก**หรือสร้าง**ฉบับแทนที่** พร้อมเก็บฉบับเดิมเป็นหลักฐานและ Audit

## บทบาทและสิทธิ์ (ขั้นต่ำ)

| การกระทำ | ผู้มีสิทธิ์ (หลักการ) |
|----------|----------------------|
| ขอยกเลิก / ยืนยันยกเลิก | ตาม RBAC ที่รับรอง (อย่างน้อยผู้มีสิทธิ์สารบรรณ/ชั้นที่ 2 หรือผู้ดูแล — **รายละเอียด role รอขยายในค่าสิทธิ์**) |
| สร้างฉบับแทนที่ | ผู้มีสิทธิ์สร้างเอกสาร + เส้นทางกลั่นกรองตามประเภท |
| ดูความสัมพันธ์ฉบับเดิม/ใหม่ | ผู้มีสิทธิ์อ่านเอกสารนั้น |

ห้าม UI เป็นจุดตัดสินสิทธิ์ — Backend ตรวจทุกครั้ง

## สถานะที่เกี่ยวข้อง

- `ยกเลิก` — ฉบับเดิมถูกทำเครื่องหมายยกเลิก เนื้อหา/PDF รุ่นเดิมคงอยู่  
- `ฉบับแทนที่` (หรือเทียบเท่าตามทะเบียนสถานะใน docs/01: `ฉบับแทนที่`) — ฉบับเดิมถูกแทนที่โดยเอกสารใหม่  
- ฉบับใหม่เดิน workflow ปกติจนออกเลข (ถ้าต้องการเลขใหม่)

## Flow — ยกเลิก

1. ผู้มีสิทธิ์เลือกเอกสารที่สถานะอนุญาตให้ยกเลิก (อย่างน้อยหลังออกเลข; ก่อนออกเลขอาจใช้สถานะอื่น — **รอขยายถ้าต้องการยกเลิกร่าง**)  
2. ระบุเหตุผลภาษาไทย  
3. ระบบตรวจสิทธิ์ → เปลี่ยนสถานะเป็น `ยกเลิก` → **ไม่**แก้เนื้อหารุ่นที่ล็อก  
4. บันทึก Audit: ผู้กระทำ เวลา ก่อน/หลัง เหตุผล รหัสเอกสาร  
5. แจ้งเตือนผู้เกี่ยวข้อง (เมื่อมีศูนย์แจ้งเตือน)

## Flow — ฉบับแทนที่

1. ผู้มีสิทธิ์เลือกฉบับเดิม (ออกเลขแล้วหรือตามกฎที่รับรอง)  
2. ระบบสร้าง**เอกสารใหม่** คนละ `รหัสเอกสาร`  
3. ตั้ง `รหัสเอกสารต้นฉบับ` บนฉบับใหม่ และทำเครื่องหมายฉบับเดิมเป็น `ฉบับแทนที่`  
4. ฉบับเดิมคง PDF/เนื้อหารุ่นเดิมเป็นหลักฐาน  
5. ฉบับใหม่เข้า workflow ร่าง→… ตามประเภทหนังสือ  
6. Audit ทั้งสองฝั่ง + รหัสอ้างอิงสองทาง  
7. เมื่อฉบับใหม่ออกเลข: เลขตามกฎทะเบียน — **ไม่**เขียนทับเลขฉบับเดิม

## กรณีผิดพลาด

| กรณี | พฤติกรรม |
|------|----------|
| ไม่มีสิทธิ์ | ปฏิเสธ ภาษาไทย |
| พยายามแก้ทับเนื้อหาหลังออกเลข | ปฏิเสธ แนะนำยกเลิก/แทนที่ |
| เอกสารไม่อยู่ในสถานะที่อนุญาต | ปฏิเสธพร้อมสถานะปัจจุบัน |
| สร้างแทนที่ซ้ำโดยไม่ผ่านกฎ | ปฏิเสธ / ใช้ idempotency ตามออกแบบภายหลัง |

## Acceptance Criteria

1. เอกสารออกเลขแล้วไม่สามารถบันทึกทับรุ่นเนื้อหาที่ล็อกได้  
2. การยกเลิกเปลี่ยนสถานะและเก็บฉบับเดิม + Audit + เหตุผล  
3. ฉบับแทนที่เป็นเอกสารใหม่ อ้างกลับต้นฉบับได้ทั้งสองทาง  
4. รายงานแยกจำนวนยกเลิก/แทนที่ ออกจากจำนวนออกเลขสำเร็จ (`docs/data-dictionary.md` ชีตสรุปรายงาน)  
5. UI รายละเอียดเอกสารแสดงความสัมพันธ์ฉบับเดิม/ใหม่ (Phase UI)  
6. มี Unit Test กฎสถานะเมื่อมีโค้ด; E2E หลัง Gate S  

## ขอบเขตไม่ทำใน DCS-P0-001

- กำหนดรายชื่อ role ยกเลิกแบบละเอียดถ้ายังไม่มีตารางสิทธิ์รับรอง  

## ผลกระทบ Backup / Report / Audit

- Backup ต้องรวมเอกสารยกเลิก/แทนที่และไฟล์ PDF เดิม  
- Audit บังคับทุกการเปลี่ยนสถานะเหล่านี้  
- สรุปภาระงาน/ออกเลขไม่นับปนกับยกเลิก-แทนที่
