## ชื่อชีตบันทึก (บังคับ — ยึด docs/00)

`บันทึกการสำรองและกู้คืนข้อมูล`

คอลัมน์บังคับ:  
`รหัสบันทึก`, `ประเภทการปฏิบัติการ`, `เวลาเริ่ม`, `เวลาสิ้นสุด`, `สถานะ`, `Checksum`, `ตำแหน่งจัดเก็บ`, `ผู้ดำเนินการ`, `ผลการทดสอบกู้คืน`, `รายละเอียดข้อผิดพลาด`

### ค่า `ประเภทการปฏิบัติการ`

- `สำรอง`  
- `ทดสอบกู้คืน`  
- `กู้คืนจริง`  
- `ล้มเหลว` (หรือบันทึกสถานะล้มเหลวคู่กับการพยายามชนิดอื่น)

## รอบสำรอง (ข้อเสนอปฏิบัติการ — ไม่ใช่ RPO/RTO ที่รับรอง)

| รอบ | ขอบเขต |
|-----|--------|
| รายวัน | ข้อมูลเปลี่ยนแปลง, Audit, PDF/ไฟล์ใหม่ |
| รายสัปดาห์ | สำเนาเต็ม Sheets, ไฟล์, ค่าตั้งค่า, โค้ดที่ deploy |
| รายเดือน | Export ระยะยาว (เช่น Excel/CSV ตามที่รับรองภายหลัง) |

ค่า **RPO/RTO/ระยะเก็บจริง** = **ADR-04 Deferred** — รอผู้รับผิดชอบ IT

## กฎกู้คืน

1. ทำได้เฉพาะ**พื้นที่ทดสอบหรือปลายทางว่าง**  
2. **ห้ามกู้ทับ Production**  
3. ตรวจ Checksum / ความครบถ้วนก่อนประกาศสำเร็จ  
4. บันทึกทุกครั้งลงชีตบันทึก + Audit  
5. แจ้งเตือนเมื่อสำรอง/กู้คืนล้มเหลว (เมื่อมีศูนย์แจ้งเตือน)

## เกณฑ์ก่อน Production (Gate P)

- มีหลักฐาน **Restore Test ผ่าน** อย่างน้อยหนึ่งรอบบน Staging/พื้นที่ทดสอบ  
- Contract นี้ถูกอ้างใน runbook  
- D-04 ได้รับการรับรองหรือมีข้อยกเว้นเป็นลายลักษณ์จากผู้มีอำนาจ (ห้าม Agent ออกข้อยกเว้นเอง)

## Audit เหตุการณ์ขั้นต่ำ

- เริ่ม/จบสำรอง  
- เริ่ม/จบทดสอบกู้คืน  
- เริ่ม/จบกู้คืนจริง  
- ล้มเหลวพร้อมรหัสข้อผิดพลาดภาษาไทยที่ปลอดภัย (ไม่เปิดเผย secret)
