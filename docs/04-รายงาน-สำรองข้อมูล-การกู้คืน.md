# รายงาน สำรองข้อมูล และการกู้คืน

ยึด `docs/00-แผนหลักระยะที่-1.md`, `docs/data-dictionary.md`, `docs/backup-restore-contract.md`  
(อัปเดต DCS-P0-001: ชื่อชีตและโครงสรุปรายงาน)

## รายงาน

ระบบสร้างข้อมูลสรุปเมื่อเกิดเหตุการณ์สำคัญ ไม่สแกนข้อมูลดิบทั้งหมดทุกครั้งที่เปิดรายงาน

### ชีตที่เกี่ยวข้อง (ตามแผนหลัก 17 ชีต)

| ชีต | หน้าที่ |
|-----|--------|
| `สรุปรายงาน` | ข้อมูลสรุปสำหรับหน้ารายงาน (สร้าง/อัปเดตอัตโนมัติเมื่อเกิดเหตุการณ์สำคัญ) — แยกจำนวนเอกสารไม่ซ้ำ, ภาระงานกลั่นกรอง, ออกเลขสำเร็จ, ยกเลิก, ฉบับแทนที่ |
| `บันทึกการสร้างรายงาน` | บันทึกวันเวลา ผู้สร้าง/ระบบ ประเภทรายงาน สถานะ |

ตัวกรองขั้นต่ำ: ช่วงวันที่, ปีงบประมาณ, หน่วยงาน, รวมหน่วยงานย่อย, ประเภทหนังสือ, สถานะ, ผู้ร่าง และผู้กลั่นกรอง

เกณฑ์ latency (เช่น P95) ใน `docs/05` เป็น**เกณฑ์ที่ต้องพิสูจน์ด้วยผลทดสอบ** ไม่ใช่คำรับประกันล่วงหน้า

## สำรองข้อมูล

| รอบ | ขอบเขต |
|---|---|
| รายวัน | ข้อมูลเปลี่ยนแปลง, Audit Log, PDF และไฟล์ใหม่ |
| รายสัปดาห์ | สำเนาเต็มของ Sheets, ไฟล์เอกสาร, ค่าตั้งค่า และโค้ดที่ deploy |
| รายเดือน | Export เป็น Excel/CSV และสำเนาระยะยาว (รายละเอียดระยะเก็บจริงรอ ADR-04) |

เก็บสำรองแยกจากพื้นที่ปฏิบัติงาน และบันทึกทุกครั้งในชีต:

### `บันทึกการสำรองและกู้คืนข้อมูล`

คอลัมน์: `รหัสบันทึก`, `ประเภทการปฏิบัติการ` (สำรอง / ทดสอบกู้คืน / กู้คืนจริง / ล้มเหลว), `เวลาเริ่ม`, `เวลาสิ้นสุด`, `สถานะ` (สำเร็จ / ล้มเหลว), `Checksum`, `ตำแหน่งจัดเก็บ`, `ผู้ดำเนินการ`, `ผลการทดสอบกู้คืน`, `รายละเอียดข้อผิดพลาด`

ต้องทดสอบกู้คืนอย่างน้อยตามรอบที่รับรองไปยัง**พื้นที่ทดสอบ** โดย**ห้ามกู้ทับข้อมูลจริง/Production**

รายละเอียดสัญญา: `docs/backup-restore-contract.md`

## ค่าที่ต้องรับรอง

ต้องกำหนดและรับรอง RPO, RTO, ระยะเก็บสำรอง และผู้รับผิดชอบก่อนเปิดใช้จริง (**ADR-04 Deferred**)  
**ห้าม Production** ก่อนผ่าน Restore Test
